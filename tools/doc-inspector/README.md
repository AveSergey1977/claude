# Сканер скрытого содержимого и сверка юридического перевода

Два самостоятельных приложения на общей библиотеке разбора файлов. Файлы обрабатываются в браузере и никуда не отправляются.

| Приложение | Страница | Что делает |
|---|---|---|
| Сканер скрытого содержимого | `dist/scanner.html` | ищет скрытое и активное содержимое в TXT, DOC, DOCX/DOCM, RTF, PDF; тип файла определяется по содержимому |
| Сверка юридического перевода | `dist/translator.html` | сверяет оригинал и перевод (RU, EN, LT) из файла или вставленного текста; для загруженного файла показывает краткую сводку скрытого содержимого и исключает скрытый и удалённый текст из сравнения |

Каждая страница самодостаточна. Внешние ресурсы — pdf.js 3.11.174 и JSZip 3.10.1 с cdnjs. Адреса опубликованных страниц для перекрёстных ссылок в подвале берутся из `links.json`.

Код: `src/lib/` — разбор форматов и проверки (общие), `src/common.js` — общие функции интерфейса, `src/app-scan.js` и `src/app-translate.js` — интерфейсы приложений, `src/shell-*.html` — разметка страниц, `src/styles.css` — общие стили.

## Что ищет сканер

| Группа | Проверки |
|---|---|
| Скрытый текст | атрибут «скрытый» (прямое форматирование и стили), цвет текста = цвету фона с учётом заливки текста, абзаца, ячейки, фигуры и цвета страницы, цвета темы, шрифт ≤ 2 пт, сжатие по ширине, вертикальный сдвиг, надписи нулевого размера и за пределами страницы, docVars, glossary, customXml, замещающий текст рисунков. PDF: проверка видимости по отрисовке каждого текстового фрагмента (белый на белом, режим отрисовки 3, текст под фигурой), текст вне страницы, скрытые слои, скрытые пометки и поля |
| Инструкции для ИИ | шаблоны на RU/EN/LT; символы-теги Unicode (расшифровываются), данные в селекторах вариантов, Base64. В скрытом месте — «критично», в видимом — «внимание» |
| Символы | нулевой ширины, bidi (RLO и др.), управляющие, PUA, мягкие переносы, слова из букв разных алфавитов |
| Правки и комментарии | непринятые удаления и вставки с перечнем удалённого текста, комментарии с авторами, прежние редакции PDF с отличающимися строками, изменения после электронной подписи |
| Активное содержимое | макросы VBA, DDE/DDEAUTO, INCLUDETEXT/INCLUDEPICTURE, внешний шаблон, внешние связи и картинки, OLE, ActiveX, altChunk, JavaScript и /Launch в PDF, вложения (проверяются рекурсивно) |
| Метаданные | автор, последний редактор, организация, шаблон, время правки, свойства XMP |

## Что сравнивает проверка перевода

Пункты выравниваются по нумерации: текстовой и автонумерации Word. Если нумерации нет, выравнивание идёт по длине абзацев. Для каждой пары пунктов сравниваются:

- числа (русский, английский и литовский форматы, неоднозначные случаи вроде `1.500` проверяются в обоих прочтениях);
- даты в словесной и числовой форме;
- суммы с валютой, в том числе «млн / million»;
- IBAN, BIC, e-mail, URL, регистрационные номера;
- объём текста относительно среднего по документу.

По документу в целом проверяются: наименования компаний с организационно-правовой формой, латиница в русском тексте, диакритика литовских имён, определённые термины, глоссарий пользователя с допустимыми и нежелательными вариантами, непереведённые фрагменты, типографика. Смысл и стиль перевода не оцениваются.

## Ограничения

- DOC: Word 97 и новее; зашифрованные файлы не открываются. Цвет страницы и цвета темы считаются стандартными.
- RTF: стили берутся из прямого форматирования, которое пишут Word и LibreOffice.
- PDF: проверка видимости выполняется для первых 150 страниц. Таблицы кодировок CMap не загружаются, поэтому текст в некоторых азиатских кодировках может не извлечься. Поиск ключевых слов по сырому файлу не видит объекты внутри потоков объектов.
- Белый текст поверх картинки в DOCX/DOC отмечается как текст цвета фона: фон картинки не анализируется.

## Сборка и тесты

```sh
node build.mjs                                   # src/ → dist/scanner.html, dist/translator.html
python3 test/make_fixtures.py                    # нужны python-docx, reportlab, pypdf, LibreOffice
node test/make_sample_files.cjs <node_modules>   # встроенный пример → test/fixtures/sample.docx
node test/run_tests.mjs <node_modules> [--shots <dir>]
```

`<node_modules>` — каталог с установленными `pdfjs-dist@3.11.174` и `jszip@3.10.1`. Тест подставляет их вместо CDN, загружает обе страницы в Chromium через Playwright, проверяет каждый тестовый файл на найденные закладки и чистые контрольные образцы (белый текст в тёмной ячейке, белый текст на чёрном в PDF), затем проверяет интерфейс на ширине телефона и компьютера в светлой и тёмной теме.
