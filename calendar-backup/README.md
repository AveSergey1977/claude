# Calendar Backup

Автоматическое резервное копирование календарей (Google, iCloud, любые CalDAV, ICS-ссылки, все календари Calendar.app на Mac) в локальную папку и на Google Drive, а также инкрементальная локальная копия Gmail. Управление — через локальную панель `http://127.0.0.1:8765`.

## Что делает

| Функция | Реализация |
|---|---|
| Расписание | По умолчанию каждые 6 ч; меняется в панели (от 15 мин до 7 дней) без перезапуска. Отсчёт по настенным часам: если Mac спал, просроченная копия создаётся сразу после пробуждения. После сбоя — повтор не позднее чем через 1 ч. |
| Копия | Один zip на запуск: `<источник>/<календарь>.ics` + `manifest.json`; для Google дополнительно `<календарь>.json` (полный ответ API без потерь). Архив проверяется (`testzip`) до публикации. |
| Этот компьютер | `~/CalendarBackups/calendar-backup-ГГГГММДД-ЧЧММСС.zip`; распакованная последняя копия — `~/CalendarBackups/latest/`. Хранится 120 последних (≈30 дней при 6 ч), настраивается. |
| Google Drive | Папка «Calendar Backups» в «Моём диске». Режим `api` (загрузка через Drive API, доступ только к файлам, созданным программой — scope `drive.file`) или `folder` (копирование в папку Google Drive для компьютера). Хранится 120 последних, настраивается. |
| Панель | Частота; сколько копий хранить; включение Drive и отдельных источников; размер последней копии (сжатый и несжатый); объём всех локальных копий; время, способ запуска, результат, размер, число календарей и записей, длительность и подробности последних 5 запусков; кнопка «Создать копию сейчас»; «Открыть папку». |
| Ошибки | Результат «Частично», если отказал один источник или Drive; «Ошибка», если данных нет (архив не создаётся, старые копии не затираются). Уведомление macOS при любом сбое. Журнал: `~/Library/Application Support/CalendarBackup/calbackup.log`. |

## Gmail

| Функция | Реализация |
|---|---|
| Что копируется | Все письма ящика, включая «Отправленные», черновики и Корзину; «Спам» — только при `"include_spam": true`. Каждое письмо — исходный файл RFC 822 (`.eml`) в том виде, в каком его отдаёт Gmail API, без пересборки. |
| Где | `~/MailBackups/<адрес>/messages/ГГГГ/ММ/<id>.eml`, индекс `index.sqlite` (метки, отправитель, тема, дата, SHA-256), список меток `labels.json`. Папка — права `700`, файлы — `600`. |
| Расписание | По умолчанию каждый час; меняется в панели (от 15 мин до суток). Первая загрузка большого ящика идёт частями: не дольше `max_minutes_per_run` (50 мин) за запуск, следующая часть — через 30 с после окончания предыдущей. |
| Изменения | После первой загрузки — только изменения через историю Gmail (новые письма, удаления, метки). Раз в `reconcile_days` (7 дней), а также если Gmail больше не хранит точку истории, — полная сверка списка писем. |
| Удалённые в Gmail | Не удаляются из копии: в индексе отмечается дата исчезновения из ящика. Если при сверке исчезло ≥ 5 % писем (не менее 20), запуск получает статус «Частично» с предупреждением. |
| Целостность | Запись через временный файл; каждый запуск перепроверяет SHA-256 у 50 случайных писем; полная проверка — `calbackup gmail-verify`. Загрузка останавливается, если на диске меньше `min_free_gb` (5 ГБ). |
| Google Drive | Копия Gmail на Google Drive **не загружается**: это тот же аккаунт Google, и при его потере или взломе такая копия пропала бы вместе с почтой. Независимая копия — «Вторая копия» ниже. |

Включение:

1. В Google Cloud Console в том же проекте: APIs & Services → Library → включить **Gmail API**.
2. `calbackup auth-google` — повторно, чтобы выдать разрешение на чтение почты (`gmail.readonly`). На экране согласия отметьте все пункты. До повторной авторизации календари копируются как прежде, а Gmail сообщает, что доступа нет.
3. В панели отметить «Копировать Gmail» и сохранить (или `"gmail": {"enabled": true}` в `config.json`).

`gmail.readonly` относится к разрешениям с ограниченным доступом ([Google: Gmail API scopes](https://developers.google.com/gmail/api/auth/scopes)). Для приложения типа **Internal** в Google Workspace проверка приложения Google не требуется; при типе External в статусе Testing действует то же ограничение на 7 дней, что и для календарей (см. ниже). Администратор Google Workspace может запретить сторонним приложениям доступ к Gmail; тогда авторизация завершится ошибкой.

Восстановление: `calbackup gmail-export --out ~/Desktop/mail.mbox` (фильтры `--label`, `--since`, `--until`, `--skip-gone`) создаёт файл mbox, который импортируется в Apple Mail (Файл → Импорт почтовых ящиков) или Thunderbird. Отдельное письмо `.eml` открывается двойным щелчком.

## Вторая копия (вне Google)

Зашифрованная копия архивов календарей и копии Gmail в хранилище, не связанном с аккаунтом Google. Используется [restic](https://restic.net): данные шифруются на Mac до отправки, повторяющиеся части хранятся один раз, данные сжимаются. Восстановить копию можно на любом компьютере стандартной программой restic, зная адрес хранилища и пароль; эта программа для восстановления не нужна.

| Функция | Реализация |
|---|---|
| Что копируется | Папка архивов календарей (без распакованной `latest/` и временных файлов), копия Gmail (письма `.eml`), служебная папка: согласованный снимок индекса Gmail, `config.json` (без паролей и токенов), `RESTORE.txt` с порядком восстановления |
| Куда | Одно или несколько хранилищ (`offsite.targets`): Hetzner Storage Box по SFTP (рекомендуется), любое S3-совместимое хранилище, внешний диск. Внешний диск, не подключённый в момент запуска, пропускается |
| Расписание | По умолчанию раз в сутки; меняется в панели |
| Срок хранения | 14 ежедневных, 8 еженедельных, 24 ежемесячных и 10 ежегодных копий (`offsite.keep`); очистка старых копий раз в неделю |
| Проверка | Раз в неделю `restic check` с чтением 5 % данных; в панели — объём хранилища и результат проверки |
| Ошибки | Статус «Частично» или «Ошибка» и уведомление macOS; отдельно — предупреждение, если у хранилища нет успешной копии дольше 3 дней (`stale_days`) |
| Секреты | Пароль хранилища и ключи облачных хранилищ — в Связке ключей; restic получает их через окружение процесса, не через командную строку |

**Пароль хранилища — единственный ключ к копии.** Если он утрачен, копию не восстановит никто, включая Вас и поставщика хранилища. Запишите его и храните отдельно от Mac.

### Настройка: Hetzner Storage Box

Storage Box — хранилище Hetzner Online GmbH (Германия) с доступом по SFTP. Тариф BX11 — 1 ТБ ([Hetzner: BX11](https://www.hetzner.com/de/storage/storage-box/bx11/)).

1. Заказать Storage Box и в консоли Hetzner включить **SSH support** (порт 23) ([Hetzner: Storage Box](https://docs.hetzner.com/storage/storage-box/general)).
2. Включить **автоматические снимки** Storage Box (например, ежедневно) ([Hetzner: Creating snapshots](https://docs.hetzner.com/storage/storage-box/getting-started/creating-snapshots)). Снимками управляет консоль Hetzner, а не SSH-ключ на Mac, поэтому при краже ключа удалённые копии восстанавливаются из снимка.
3. Ключ для доступа без пароля:
   ```bash
   calbackup offsite-ssh-key
   ```
   и выполнить выведенную команду `cat … | ssh -p23 uXXXXX@uXXXXX.your-storagebox.de install-ssh-key` — один раз потребуется пароль Storage Box ([Hetzner: Add SSH keys](https://docs.hetzner.com/storage/storage-box/ssh-keys/add-ssh-keys)).
4. Пароль хранилища (создаётся случайный и сохраняется в Связке ключей; запишите его):
   ```bash
   calbackup offsite-password
   ```
5. В `config.json` в разделе `offsite.targets` заменить `uXXXXX` на имя пользователя Storage Box; `repository` — `sftp://uXXXXX@uXXXXX.your-storagebox.de:23/restic-mac`.
6. В панели отметить «Создавать вторую копию» и сохранить. Хранилище создаётся при первом запуске. Первая копия большого ящика Gmail может занять часы.

### Другие хранилища

| Хранилище | `repository` | Дополнительно |
|---|---|---|
| Внешний диск | `/Volumes/<Диск>/restic` | — |
| S3-совместимое (Backblaze B2, Wasabi, AWS) | `s3:https://<endpoint>/<bucket>/restic` | `"env_keyring": {"AWS_ACCESS_KEY_ID": "s3-id", "AWS_SECRET_ACCESS_KEY": "s3-key"}` и `calbackup set-secret s3-id`, `calbackup set-secret s3-key`. Для ключа без права удаления — `"prune": false` |

### Восстановление

| Команда | Действие |
|---|---|
| `calbackup offsite-snapshots` | Список копий в хранилище |
| `calbackup offsite-restore --to ~/Restore` | Последняя копия в пустую папку (`--snapshot ID` — другая копия) |
| `calbackup offsite-check --full` | Полная проверка с чтением всех данных |
| `calbackup restic -- <команда>` | Любая команда restic с настройками хранилища |

Без этой программы: `restic -r <repository> restore latest --target ~/Restore` (для Storage Box дополнительно `-o sftp.args="-i <ключ>"`); порядок — в `offsite-meta/RESTORE.txt` внутри копии.

## Источники

| `type` | Что охватывает | Точность |
|---|---|---|
| `google` | Все календари из списка Google Calendar аккаунта (свои, общие, подписки), через Calendar API | Серии событий с правилами повтора, исключения, отменённые вхождения (EXDATE), участники, напоминания, ссылки Meet; плюс исходный JSON |
| `caldav` | iCloud (`https://caldav.icloud.com`), Fastmail, Яндекс, Nextcloud и др. Включая списки Напоминаний (VTODO) | Объекты сохраняются в том виде, в каком их отдаёт сервер |
| `ics` | Любой календарь, опубликованный ссылкой `.ics`/`webcal://`: «секретный адрес» Google, публикация Outlook/Office 365, подписки | Как опубликовано |
| `macos` | Все аккаунты, подключённые к Calendar.app на этом Mac (в т.ч. Exchange/Outlook, Yahoo, «Дни рождения») | Повторяющиеся события сохраняются развёрнутыми по вхождениям в окне −10…+5 лет. Резервный «сборщик всего остального» |

## Установка (macOS)

```bash
git clone https://github.com/avesergey1977/claude.git && cd claude/calendar-backup
./install-macos.sh
```

Скрипт создаёт виртуальное окружение в `~/Library/Application Support/CalendarBackup`, устанавливает restic (из Homebrew, если он есть, иначе официальный выпуск 0.19.1 с проверкой SHA-256 по файлу сумм выпуска), команду `~/.local/bin/calbackup` и LaunchAgent `com.calendar-backup.agent` (запуск при входе в систему, перезапуск при сбое). Повторный запуск обновляет программу, сохраняя настройки, токены и историю. Удаление: `./uninstall-macos.sh` (копии в `~/CalendarBackups` не удаляются).

Настройки: `~/Library/Application Support/CalendarBackup/config.json` (создаётся из `config.example.json`).

### Куда сохранять

В панели, раздел «Настройки → Куда сохранять», задаются две папки: для архивов календарей и для копии Gmail. Путь вводится вручную (`~/Backups`, `/Volumes/Диск/Backups`) или выбирается кнопкой «Выбрать…» в окне macOS. Пустое поле означает стандартную папку: `~/CalendarBackups` и `~/MailBackups`.

- **Проверка при сохранении:** нужен полный путь; домашняя папка, корень диска и служебная папка программы не принимаются; папка создаётся, и в неё делается пробная запись. Если macOS не даёт доступа (папки «Документы», «Рабочий стол», iCloud Drive, внешние диски), разрешите его программе python: Системные настройки → Конфиденциальность и безопасность → Файлы и папки или Полный доступ к диску.
- **Перенос уже сохранённого** (флажок включён по умолчанию). Архивы календарей переносятся всегда, в том числе на другой диск: они небольшие. Копия Gmail переносится только в пределах одного диска, мгновенным переименованием. На другой диск копия Gmail автоматически не переносится: прежняя остаётся на месте, в новой папке письма загружаются заново. Чтобы не загружать их повторно, выключите копирование Gmail, скопируйте папку аккаунта в Finder в новую папку, затем включите его снова. Без флажка прежние копии остаются на месте.
- **Во время копирования** папку этого вида копий сменить нельзя: панель попросит дождаться окончания.
- **Внешний диск.** Если папка находится на диске `/Volumes/…`, который сейчас не подключён, запуск завершается ошибкой и ничего не записывает. Без этой проверки путь был бы молча создан на системном диске. После правки файла вручную: `launchctl kickstart -k gui/$(id -u)/com.calendar-backup.agent`.

## Подключение источников

### Google Calendar и Google Drive (режим `api`)

1. [Google Cloud Console](https://console.cloud.google.com/) → создать проект.
2. APIs & Services → Library → включить **Google Calendar API** и **Google Drive API** (для копии почты — также **Gmail API**).
3. OAuth consent screen → User type **Internal** (доступен для аккаунтов Google Workspace). При типе External в статусе Testing refresh-токен истекает через 7 дней и копирование Google будет прекращаться еженедельно ([Google: Refresh token expiration](https://developers.google.com/identity/protocols/oauth2#expiration)).
4. Credentials → Create credentials → OAuth client ID → **Desktop app** → скачать JSON и сохранить как
   `~/Library/Application Support/CalendarBackup/google_client_secret.json`.
5. `calbackup auth-google` — откроется браузер; разрешения: чтение календарей, доступ к файлам, созданным приложением, и чтение почты.

Ограничить набор календарей: `calendar_ids` (только перечисленные) или `exclude_ids`.

### iCloud

1. [account.apple.com](https://account.apple.com) → Вход и безопасность → Пароли приложений → создать ([Apple: app-specific passwords](https://support.apple.com/en-us/102654)).
2. В `config.json` у источника `icloud` указать `username` (Apple ID).
3. `calbackup set-secret icloud` — ввести пароль приложения; он хранится в Связке ключей macOS, не в `config.json`.

Другие CalDAV-серверы — по образцу `icloud` со своим `url`, `username` и именем секрета.

### Все календари Mac (`macos`)

1. В `config.json` поставить `"enabled": true` у источника `mac`.
2. `calbackup grant-macos` — macOS запросит доступ к Календарю и выведет список найденных календарей. Если запроса нет: Системные настройки → Конфиденциальность и безопасность → Календари.
3. Исключить аккаунты, уже охваченные `google`/`caldav`: `"exclude_accounts": ["iCloud", "you@example.com"]` (имена — из вывода шага 2).

### Ссылки ICS

Секретные адреса содержат токен доступа; храните их в Связке ключей: `calbackup set-secret outlook-ics`, в конфиге — `{"keyring": "outlook-ics"}`. Открытую ссылку можно указать строкой.

### Вариант без Google Cloud

`"drive": {"mode": "folder"}` — копирование в папку Google Drive для компьютера (определяется автоматически в `~/Library/CloudStorage/GoogleDrive-*/My Drive`, иначе `folder_path`). Календари Google — источником `ics` по «секретному адресу в формате iCal» ([Google: Share your calendar](https://support.google.com/calendar/answer/37648)). Ограничение: такой адрес не передаёт напоминания, и его нужно добавлять для каждого календаря отдельно.

## Восстановление

Файл `.ics` из архива импортируется в Google Calendar (Настройки → Импорт и экспорт), Calendar.app (Файл → Импорт) или Outlook. Импорт добавляет события в выбранный календарь; при импорте в непустой календарь возможны дубликаты.

## Безопасность

- Панель слушает только `127.0.0.1`; изменяющие запросы требуют токен, выдаваемый странице при запуске; запросы с чужим `Host` отклоняются.
- Пароли и секретные ссылки — в Связке ключей; OAuth-токен Google и настройки — в файлах с правами `600`.
- Архивы и копия Gmail на Mac не шифруются: их защищает FileVault; на Google Drive — доступ к аккаунту. Вторая копия шифруется restic до отправки. Копия Gmail индексируется Spotlight, как и другие файлы пользователя.

## Тесты

```bash
pip install -r requirements.txt && python3 -m unittest discover -s tests -v
```

Тесты второй копии выполняются с настоящим restic (`RESTIC_BIN` или `restic` в `PATH`), тест SFTP — при наличии `sshd` и прав root; иначе они пропускаются.
